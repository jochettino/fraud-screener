# fraud-screener

Fraud screening API for outbound bank transfers (Ktor/Netty). Screening and instrument lookup are currently mocked.

## Prerequisites

- JDK 21 (Gradle toolchain; auto-provisioned if missing)

## Commands

```
./gradlew build
./gradlew test              # unit tests only
./gradlew integrationTest   # needs Docker
./gradlew :fraud-screener-api:run   # listens on $PORT, default 8080
```

## Run with Docker

```
docker build -t fraud-screener-api .
docker run -p 8080:8080 fraud-screener-api
curl localhost:8080/health   # {"status":"UP"}
```

## API

| Endpoint | Description | Expected response |
|----------|-------------|-------------------|
| `GET /health` | Liveness check | 200 `{"status":"UP"}` |
| `POST /v1/banktransfer/outbound` | Screen an outbound bank transfer (screening/lookup mocked) | 200 `{"status": "PASSED" \| "REJECTED" \| "HELD"}`, 404 unknown instrument, 400 bad format |
| `GET /swagger` | Swagger UI | 200 HTML (e.g. http://localhost:8080/swagger) |

Mock rules:

- instrument ids starting with `00000000-` -> 404
- amount > 10000 -> HELD
- reference containing `fraud` (case-insensitive) -> REJECTED
- otherwise -> PASSED

### Contract and DTOs

`fraud-screener-api/src/main/resources/openapi/fraud-screener-api.yaml` is the source of truth. DTOs are generated by the `openApiGenerate` task (runs before `compileKotlin`) into `build/generated/openapi`, package `adapter.http.dto`; never hand-write them. They stay in the adapter layer.

## CI

GitHub Actions (`.github/workflows/ci.yml`) runs on pull requests to `main` (and manually). The single job `build-and-test` runs `./gradlew build`, which includes `integrationTest` (`check` depends on it): it builds the Docker image via Testcontainers and checks `/health` and that the container runs as non-root.

## Layout

- `fraud-screener-api` - Kotlin/Ktor service, hexagonal packages under `com.jochettino.fraudscreener.api`:
  `domain`, `application` (`port/in`, `port/out`, `service`), `adapter` (`in/http`, `out`), `config`.
